작성일: 2026-09-05
대상: Claude Code 구현 핸드오프

## 1. 한 줄 정의
**플레이어는 대대장이다.** 10개 부대(각 50명)의 **태세(stance)** 를 설정하고, 부대가 그 태세에 따라 스스로 싸우는 것을 실시간 지도에서 지켜보며, 태세를 바꾸는 **타이밍**으로 승부한다. 유닛 직접 조작, 이동 지점 지정, 목표 지정은 없다.
## 2. 설계 기둥 (모든 결정의 판단 기준)
1. **명령이 아니라 상태.** 플레이어 입력은 부대별 태세 스위치 하나뿐. 목표·경로·대형을 지정할 수 없다.
2. **부대는 설득력 있게 자율적이다.** 부대가 멍청하면 짜증, 그럴듯하면 자책. 게임의 질은 부대 AI의 질이다.
3. **지도는 정직하다.** 부대 위치·이동·교전·사기가 실시간으로 보인다. 정보 마찰은 없다(표준 fog of war만).
4. **사기가 전투를 결정한다.** 병력 손실보다 사기 붕괴로 전투가 끝난다.
5. **결정적 시뮬레이션.** 같은 입력 = 같은 결과. 리플레이·테스트·AI 대전 배치가 가능해야 한다.
## 3. 프로토타입 범위
### 포함 (P0)
- 1개 맵 (약 1.5km × 1.0km, 지형 3종: 평지 / 숲 / 언덕)
- 양측 각 10개 부대, 부대당 50명, 병과 3종 (선보병 / 기병 / 포병)
- 태세 5종 + 자동 전이 규칙
- 지휘관 성향 2축 (공격성, 냉정함)
- 전투 전 배치 화면 (플레이어 측 배치 구역 내 드래그)
- 적 AI: 동일 부대 AI + 단순 전략 스크립트
- 승패 판정 및 결과 화면
- 개별 병사 렌더링 (500 스프라이트/측)
- AI vs AI 헤드리스 배치 실행 (밸런싱용)
### 제외 (Non-goals)
- 캠페인/전략 층 — 전투 하나가 재미있는지 먼저 검증
- 멀티플레이 — 결정적 시뮬 구조로 대비만 함
- 3D, 애니메이션 — 2D 탑다운 스프라이트/도형으로 충분
- 시대 고증 — 흑색화약 시대의 **느낌**만 차용, 정확한 고증은 상업 단계에서
- 모바일 UI — 데스크톱 브라우저 우선
- 저장/불러오기 — 전투가 15분이라 불필요
- 사운드
## 4. 시대 및 전투 모델
**흑색화약 시대 (나폴레옹 전쟁 풍).** 선택 이유:
- 대형 유지 = 전투력이라 "재편" 태세의 의미가 명확
- 일제사격 → 돌격 → 붕괴의 시각적 극적 전개
- 사거리(약 100m)가 맵보다 훨씬 짧아 500명 스케일 지도 전투가 성립
- 부대 AI 설계 변수가 적음 (대형, 사기, 거리)
## 5. 시뮬레이션 코어
### 5.1 시간
- 고정 tick: **10 tick/초** (시뮬레이션 시간 기준)
- 게임 속도 1x / 2x / 일시정지. 일시정지 중 태세 변경 가능 (초심자 배려; 상업판에서 난이도 옵션)
- 전투 길이 목표: 실시간 10~20분
### 5.2 공간
- 연속 좌표 (미터 단위, float). 격자 아님.
- 지형은 **셀 격자**(10m 셀)로 저장: 종류(평지/숲/언덕), 고도(정수)
- 병사 충돌은 부대 내부 대형 유지에만 사용, 타 부대와는 "접촉" 판정만
### 5.3 엔티티 계층
```
Battle
 ├─ Terrain (셀 격자)
 ├─ Side[2]
 │   └─ Unit[10]
 │       ├─ Commander (성향)
 │       ├─ Stance (현재 태세 + 전이 이력)
 │       ├─ Formation (대형 종류, 방향, 앵커 위치)
 │       ├─ Morale, Fatigue, Ammo, Cohesion
 │       └─ Soldier[≤50] (위치, 목표 슬롯, 생존, 도주 여부)
 └─ EventLog (리플레이용)
```
### 5.4 병사 vs 부대의 역할 분담
- **의사결정은 부대 단위**에서만 한다. 병사는 판단하지 않는다.
- 병사는 부대가 정한 대형 슬롯을 향해 이동하고, 사거리 내 적에게 사격하며, 사기 붕괴 시 개별적으로 도주한다.
- 병사 단위 시뮬레이션의 목적은 **시각적 설득력**(흩어짐, 뭉침, 도주)이지 전투 계산의 정밀도가 아니다. 전투 계산은 부대 단위 수치로 해도 무방하며, 병사 사망은 그 결과를 시각화하는 방식으로 배분한다.
## 6. 태세(Stance) 시스템
### 6.1 태세 5종
| 태세 | 이동 | 교전 | 대형 | 사기 회복 | 핵심 행동 |
|---|---|---|---|---|---|
| **공세 (Assault)** | 적 방향 전진 | 적극 | 돌격 대형 | 없음 | 가장 가치 높은 적을 자체 선택해 접근·사격·돌격 |
| **방어 (Hold)** | 미세 조정만 | 접근하는 적에만 | 횡대 | 느림 | 근처 유리 지형으로 소폭 이동 후 고정, 사격 우선 |
| **은폐 (Screen)** | 적 회피 | 회피, 피격 시 방어 전환 | 산개 | 보통 | 발각 거리 축소, 교전 회피, 적 접근 시 후방으로 물러남 |
| **후퇴 (Withdraw)** | 아군 후방 방향 | 지연 사격만 | 종대 | 없음 | 아군 배치 기준점 방향으로 이탈, 추격 시 사격 후 계속 이탈 |
| **재편 (Rally)** | 정지 | 없음 (피격 시 강제 전환) | 밀집 | 빠름 | 도주 병사 복귀, 사기·응집 회복. 이 상태에서 피격되면 매우 취약 |
### 6.2 태세 전이
**플레이어 전이:** 언제든 5종 중 하나로 변경 가능. 전이 즉시 적용되나, **대형 변경에 시간이 걸린다**(횡대↔종대 약 20초). 대형 변경 중 전투력 저하.
**자동 전이 (부대가 스스로 바꿈):**
| 조건 | 전이 | 비고 |
|---|---|---|
| 사기 < 붕괴 임계 | 아무 태세 → **패주(Rout)** | 플레이어 개입 불가한 6번째 숨은 상태. 사기가 회복 임계를 넘어야 재편으로 복귀 가능 |
| 탄약 소진 | 공세/방어 → 방어 (사격 불가, 돌격만) | UI에 경고 |
| 재편 중 피격 | 재편 → 방어 | |
| 은폐 중 피격 | 은폐 → 방어 | |
| 방어 중 적 붕괴 목격 + 지휘관 공격성 높음 | 방어 → 공세 | **지휘관 성향이 만드는 드라마** |
| 공세 중 손실 급증 + 지휘관 냉정함 낮음 | 공세 → 후퇴 | |
| 공세 중 손실 급증 + 지휘관 냉정함 높음 | 유지 | |
자동 전이는 반드시 **이벤트 로그 + UI 알림**으로 플레이어에게 보인다. "왜 저 부대가 갑자기 돌격하지?"가 되어야지, 몰래 바뀌면 안 된다.
### 6.3 태세 내 행동 선택 (유틸리티 AI)
각 tick(또는 1초마다)에 부대는 현재 태세가 허용하는 후보 행동에 점수를 매기고 최고점을 실행한다.
예: 공세 태세의 후보 행동
- `approach(enemy)` — 점수 = 적 가치 × 거리 근접도 × 측면 노출도
- `volley(enemy)` — 점수 = 사거리 내 여부 × 탄약 × 명중 기대
- `charge(enemy)` — 점수 = 적 사기 낮음 × 거리 근접 × 아군 응집 × 지휘관 공격성
- `reposition(flank)` — 점수 = 측면 이동 가능성 × 지휘관 냉정함
**지휘관 성향은 이 점수의 가중치**다. 새 행동을 추가하는 게 아니라 같은 행동을 다르게 고르게 한다.
## 7. 지휘관 성향
2축, 각 0.0~1.0:
- **공격성 (Aggression)** — 돌격 점수 가중치 ↑, 방어→공세 자발 전환 확률 ↑, 후퇴 태세에서도 반격 시도
- **냉정함 (Composure)** — 손실에 대한 사기 하락 완화, 공세→후퇴 자발 전환 억제, 측면 기동 선호
프로토타입에서는 10부대에 성향을 고정 배정하고 배치 화면에서 표시한다. 플레이어가 "3번 부대장은 성급하다"를 알고 배치·태세 결정에 반영하는 것이 재미의 일부다.
## 8. 전투 수치 모델
### 8.1 부대 상태 변수
| 변수 | 범위 | 설명 |
|---|---|---|
| strength | 0~50 | 생존·비도주 병사 수 |
| morale | 0~100 | 붕괴 임계 25, 회복 임계 40 (지휘관 냉정함으로 ±10 조정) |
| cohesion | 0~1 | 대형 완성도. 이동·대형 변경·손실로 하락, 정지로 회복 |
| fatigue | 0~1 | 이동·돌격으로 상승, 정지로 하락. 이동 속도와 명중에 페널티 |
| ammo | 0~N | 일제사격 횟수. 프로토타입: 보병 30, 포병 20 |
### 8.2 사기 변동 요인
| 요인 | 방향 |
|---|---|
| 아군 손실 (최근 30초 내 비율) | ↓ 큼 |
| 측면/후방 피격 | ↓ 큼 |
| 인접 아군 부대 붕괴 목격 | ↓ 중 (전염) |
| 포격 피격 | ↓ 중 |
| 기병 돌격 받음 (보병, 방진 아님) | ↓ 큼 |
| 인접 아군 부대 존재 | ↑ 소 (지속) |
| 적 부대 붕괴 목격 | ↑ 중 |
| 재편 태세 | ↑ 지속 |
| 지휘관 냉정함 | 모든 ↓ 요인 완화 |
### 8.3 사격
- 사거리: 보병 100m, 포병 600m
- 일제사격 주기: 보병 20초 (tick 200), 포병 40초
- 명중 기대 사상자 = 기본 명중률 × 발사 병력 × 거리 감쇠 × 지형 엄폐 계수 × 응집도 × (1 − 피로)
- 지형 엄폐: 숲 0.5, 언덕 위 방어 시 0.7, 평지 1.0
### 8.4 근접전 (돌격)
- 돌격 부대가 적 부대와 접촉 시 **즉시 사기 판정**. 방어측 사기가 임계 이하면 접촉 전 붕괴 (역사적으로 대부분의 돌격 결말).
- 접촉 후 근접전은 초당 사상자 교환. 전투력 = strength × cohesion × 병과 계수 × 지형 계수 × 측면 보너스.
- 기병 vs 보병: 보병이 방어 태세로 정지 상태면 기병 돌격 실패 확률 높음. 보병이 이동 중/붕괴 중이면 기병 압도.
### 8.5 병과 계수
| 병과 | 이동 속도 | 사격 | 근접 | 특징 |
|---|---|---|---|---|
| 선보병 | 1.0 | 1.0 | 1.0 | 기준 |
| 기병 | 2.5 | 0 | 1.8 (돌격 시), 0.8 (정지 시) | 사격 불가. 공세 태세에서만 진가. 피로 급증 |
| 포병 | 0.5 | 3.0 (장거리) | 0.2 | 근접전 극약. 방어 태세에서만 사격. 이동 중 사격 불가 |
## 9. 승패 조건
다음 중 먼저 발생:
1. 한쪽의 **가용 부대**(패주·전멸 아닌 부대) 비율이 30% 이하
2. 한쪽 부대 전원이 맵 밖 후방으로 이탈
3. 20분 경과 시 남은 전투력(strength × morale 합) 우세 측 판정승
결과 화면: 부대별 손실, 사기 곡선 타임라인, 태세 변경 로그 (플레이어 + 자동). 이 로그가 "내가 뭘 잘못했나"를 보여주는 학습 장치다.
## 10. 적 AI (전략 층)
부대 AI는 양측 동일. 그 위에 **적군 전략 스크립트**가 부대별 태세를 결정한다. 프로토타입은 단순 규칙:
- 초기: 포병 방어, 보병 4개 방어, 보병 2개 공세, 기병 은폐
- 아군 부대 붕괴 감지 시 인접 예비 부대 공세 전환
- 자군 부대 사기 40 이하 시 후퇴 → 재편 → (회복 시) 방어
- 기병은 적 포병 또는 붕괴 부대 감지 시 공세
이걸로도 "AI가 뭔가 하는 것 같다"는 느낌이 나야 한다. 나중에 유틸리티 기반 전략 AI로 교체.
## 11. 배치 단계
- 맵 좌측 1/3이 플레이어 배치 구역, 우측 1/3이 적 배치 구역(적은 스크립트 고정 배치 3종 중 랜덤)
- 부대를 드래그해 위치·방향 설정. **이것이 플레이어의 유일한 공간적 결정**.
- 초기 태세 설정 가능 (기본값 방어)
- 배치 화면에 각 부대의 병과·지휘관 성향·병력 표시
- "전투 시작" 후 배치 변경 불가
## 12. 렌더링 및 UI
### 12.1 렌더링
- **PixiJS** 2D 탑다운
- 병사 = 작은 원/사각 (측별 색), 부대 = 병사 집합 + 외곽선 + 부대 번호 라벨
- 지형 = 셀 격자 타일 색 (숲 진녹, 언덕 등고선 표시)
- 사격 = 짧은 선/연기 이펙트, 돌격 = 부대 외곽선 강조
- 도주 병사 = 색 흐려짐 + 후방으로 흩어짐
- 카메라: 팬/줌
### 12.2 UI
- 부대 선택: 지도 클릭 또는 하단 부대 카드 (10개 상시 표시)
- 부대 카드: 번호, 병과 아이콘, 사기 바, 병력 수, 현재 태세, 지휘관 성향 아이콘
- 태세 변경: 선택 부대 카드에서 5개 버튼. 다중 선택 후 일괄 변경 가능.
- 이벤트 피드 (우측): 자동 전이, 붕괴, 돌격 성공/실패
- 상단: 시간, 속도 조절, 양측 가용 부대 수
**의도적으로 없는 것:** 이동 지점 클릭, 목표 지정, 대형 선택, 병사 개별 선택.
## 13. 기술 스택 및 아키텍처
- **언어:** TypeScript (strict)
- **패키지 구조:** pnpm workspace
  - `packages/sim` — 순수 시뮬레이션 코어. **DOM·PixiJS 의존 0**. Node에서 실행 가능.
  - `packages/ai` — 부대 AI, 적 전략 스크립트. `sim`에만 의존.
  - `apps/web` — Vite + PixiJS + 최소 UI (React 또는 순수 DOM, 프로토타입은 순수 DOM 권장)
  - `apps/headless` — CLI. 시나리오 JSON + 시드 → N판 실행 → 결과 CSV
- **결정성:** 시드 기반 PRNG (예: mulberry32). `Math.random` 사용 금지 (lint rule). 부동소수 연산 순서 고정.
- **상태:** `BattleState` 단일 직렬화 가능 객체. `step(state, inputs, rng) → state`. 렌더러는 읽기만.
- **입력:** `{ tick, unitId, stance }` 이벤트 배열. 리플레이 = 시드 + 입력 배열.
- **테스트:** vitest. 시뮬 코어는 결정성 테스트 (같은 시드·입력 → 동일 해시) + 시나리오 테스트 (예: 방어 보병 vs 돌격 기병 100판, 보병 승률 60~80%)
## 14. 시나리오/파라미터 파일
모든 수치(사거리, 사기 계수, 병과 계수, 지휘관 성향 배정, 초기 배치)는 `scenarios/*.json` + `params/default.json`으로 외부화. 코드 수정 없이 밸런싱.
## 15. 마일스톤
| 단계 | 내용 | 검증 |
|---|---|---|
| **M1 코어** | `sim` 패키지: 지형, 부대, 병사 이동, 대형, 사격, 사기, 5태세 상태 머신. 렌더 없음 | headless로 1판 실행, 결정성 테스트 통과 |
| **M2 부대 AI** | 유틸리티 행동 선택, 자동 전이, 지휘관 성향 | 헤드리스 AI vs AI 100판, 결과 분포 확인, 명백한 멍청함 제거 |
| **M3 렌더** | PixiJS로 M1/M2 시각화, 카메라, 부대 카드, 태세 버튼 | 사람이 1판 플레이 가능 |
| **M4 배치+적 AI** | 배치 화면, 적 전략 스크립트, 승패, 결과 화면 | 전투 1판 완주 |
| **M5 검증** | 5명 이상 플레이 테스트. "다시 하고 싶은가" | 여기서 진행/폐기 결정 |
M1~M2를 렌더 없이 먼저 하는 이유: 부대 AI가 게임이므로, 그림 없이 로그만으로도 전투가 그럴듯한지 확인해야 한다.
## 16. 프로토타입 성공 기준
- 플레이 테스터가 태세 변경 타이밍으로 결과를 바꿀 수 있다고 느낀다 (통제감)
- "부대가 멍청하다"보다 "내가 늦었다"는 피드백이 많다
- 같은 시나리오를 2회 이상 자발적으로 재플레이
- 헤드리스 AI 대전에서 한쪽 배치가 항상 이기지 않는다 (밸런스 기초)
## 17. 열린 질문
- **일시정지 중 명령 허용 여부** — 통제감 vs 긴장감. 프로토타입은 허용, 테스트 후 결정.
- **대형 변경 시간 20초** — 너무 길면 태세 변경이 무의미, 짧으면 태세 스위치가 마이크로 조작화. 파라미터로 두고 조정.
- **패주 부대의 재편 복귀 가능성** — 복귀 불가면 냉혹하지만 명확, 가능하면 후반 역전 여지. 프로토타입: 복귀 가능하되 병력 일부 영구 손실.
- **10부대 상시 카드가 너무 많은가** — 5개씩 2행 또는 병과별 그룹. UI 테스트로 결정.
## 18. 상업 확장 시 고려 (설계에 반영만, 구현 안 함)
- 캠페인 층 추가 시 부대의 지휘관 성향·경험이 전투 간 지속
- 멀티플레이: 입력 이벤트 동기화 (lockstep). 결정적 코어가 전제.
- 시대 교체: 병과 계수·사거리·대형 종류가 파라미터 파일 교체로 가능하도록
- 모바일: 부대 카드 UI가 터치에 맞아야 함. 지도 클릭 선택 의존 최소화.
